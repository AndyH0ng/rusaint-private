# 일반출력 신청·결제 MCP

## 범위와 실행 위치

신청·주문·승인·발급 등록 확인은 gcloud의 Rust 서버가 담당한다. 국문 재학증명서 또는
장학금지급증명서 1통의 INTERNET 상품만 지원한다. 승인은 `smart/newcertres.jsp`를 사용한다.
FILE 상품의 `filepay/newcertres.jsp`와 `CERTPDFDOWN`은 사용하지 않는다.
기존 3,000원 FILE 승인 건을 재승인하거나 복구하는 기능이 아니다.
문서 복호화와 PDF 렌더링은 기존 Python 필터를 호출한다. Windows 프로그램을 실행하지 않는다.

## MCP 도구

- `prepare_certificate_order`: 종류(`enrollment`/`scholarship`), 제출기관, 용도, 필요 시 장학금 시작·종료 학기,
  결제 상한을 받는다. 기본 상한 1,000원, 최대 10,000원. 학교 금액과 summary를 사용자에게 보여 준다.
  유료는 30분짜리 브라우저 결제 링크를 반환한다. 무료는 한 번만 발급 신청하고 같은 주문으로 상태를 확인한다.
- `certificate_order_status`: 도구가 반환한 order_id로 기존 주문을 조회한다. 새 승인이나 신청을 보내지 않는다.
  문서 등록이 확인되면 기존 MINNO Journal을 통해 PDF 발급을 이어간다. 완료 시 10분짜리 다운로드 링크를 반환한다.

카드·토스 인증은 사용자 브라우저에서만 수행한다. 긴급연락처는 브라우저에서 받아 메모리의
PG·학교 승인 필드에만 사용하며 주문 기록, 콜백 로그, 승인 응답 보존본에는 남기지 않는다.
반사된 연락처를 제거했으므로 승인 응답 보존본은 바이트 단위의 무수정 원문은 아니다.

## 상태와 복구

`preparing → ready → checkout_opened → approval_pending → approval_response_recorded`
이후 대상 문서가 보이면 `pdf_pending → complete`로 진행한다.
무료는 브라우저 PG 단계를 건너뛴다. 취소·금액 초과는 `cancelled`, 신청 준비 오류는 `preparation_failed`다.

- 승인 시도 여부를 네트워크 호출 전에 원자적으로 기록한다. 타임아웃이나 재시작 후에는
  `approval_unknown`으로 두고 보관함만 조회한다. 같은 주문을 자동 재승인하지 않는다.
- 승인 요청은 리디렉션을 따르지 않는다. 첫 응답의 본문·HTTP 상태·Location을 비공개로 보존하고,
  자동 제출 폼·리디렉션 유무를 따로 판정한다. 확인하지 않은 JavaScript나 폼을 실행하지 않는다.
- 초기 보관함 재조회는 최대 8회, 1초 간격이며 조회마다 5초 제한이다. 문서가 없으면
  `issuance_pending`, 후속 절차가 발견되면 `continuation_required`, 승인 결과 자체가 불명확하면
  `approval_unknown`을 유지한다. 이는 다시 결제하라는 오류가 아니다.
- 학교 처리는 익일 오전까지 지연될 수 있다. 같은 주문의 `certificate_order_status` 또는
  `certi_documents`로 나중에 확인한다. 계속 미확인이면 학교 주문번호와 사용자 승인 내역으로
  KICA 문의를 준비한다. 문의 전송은 자동으로 하지 않는다.
- PDF는 출력 완료 통지 전에 디스크에 저장하며, 학교 원본확인이 성공한 경우에만 공개한다.

## 중복 방지와 격리

사용자별 디렉터리 아래 주문 레코드와 LGD_OID 색인을 저장한다. 사용자당 진행 중 주문 하나만
허용하고 생성 과정을 직렬화한다. 출력은 기존 MINNO Journal을 사용해 다른 작업 ID로도 재출력하지 않는다.
PG 콜백은 일회성 티켓으로만 주문을 찾는다. 중복 필드를 거부하며, 반환된 OID·금액·MID가 있으면
학교 주문과 대조한다. PAYKEY를 제외한 콜백 값으로 원래 학교 주문을 덮어쓰지 않는다.
연락처와 PAYKEY를 포함한 요청 본문을 로그에 남기지 않고 URL의 티켓도 가린다.

금액 상한 검사는 학교 주문 생성 뒤다. 초과 시 승인은 보내지 않지만 미결제 주문은 남으며
학교 안내에 따라 자동 취소된다. 승인 전에는 화면에서 신청을 취소할 수 있다.

## 배포와 검증

자산은 `/usr/local/lib/rusaint-mcp/certi` 또는 `RUSAINT_CERTI_ASSETS`에 설치한다.
`REPORTX.exe`, Python 필터 3개, Nanum 글꼴 4개 또는 해당 시스템 글꼴이 필요하다.
StateDirectory와 CacheDirectory를 설정하고 UV_CACHE_DIR를 쓰기 가능한 캐시에 연결한다.
자격 증명은 메모리에만 있으므로 서버 재시작 후 커넥터는 다시 연결해야 한다.

검증은 단위·라우터 테스트, gcloud 무료 신청부터 원본확인 PDF 수신, 유료 주문 준비와
결제창 취소, 사용자 직접 인증을 통한 실승인 순서로 진행한다. 실승인 미검증 상태를
무료 발급 성공과 혼동해 완료로 표시하지 않는다.

### 2026-11-16 검증 결과

- Rust 신청·무료 발급, 기존 Python 필터의 PDF 생성, 학교 원본확인까지 gcloud 검증 서버에서 성공했다.
  실제 다운로드는 HTTP 200, `%PDF-` 헤더, 208,220바이트였다.
- Linux 바이너리와 자산을 운영 서버에 설치했고 StateDirectory·CacheDirectory를 적용했다.
  기존 터널은 재시작하지 않았다. 검증 서버의 완료된 무료 기록도 사용자별 소유권을 유지해 옮겼다.
- 운영 MCP에서 두 신청·조회 도구의 등록과 실제 1,000원 INTERNET 재학증명서 주문 준비를 확인했다.
  이어 사용자 브라우저 인증 후 Rust 승인·발급 등록·Python PDF 생성·학교 원본확인까지 성공했다.
  사용자 PDF 수신과 서버의 `status=complete`를 모두 확인했다. 진행 중에 표시된 `pdf_pending`은
  이후 같은 주문에서 완료됐으며 추가 승인·재결제는 하지 않았다.
  이는 INTERNET 경로의 실검증이다. 기존 3,000원 FILE 주문의 문제 해결이나 별도 PG 영수증 대조를 뜻하지 않는다.
- MCP 테스트 59개 통과·2개 제외, rusaint-certi 23개 통과, 포맷·Clippy 검사 통과.
  전체 라이브러리 테스트도 통과했으며 학교 세션 파일이 필요한 기존 테스트 2개는 명시적으로 제외했다.
